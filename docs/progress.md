# 進度與待辦

換電腦接著做時先讀這份。這裡是**最新狀態**。

## 現在只保留 v2（2026-09-30 定案）

網頁首頁（`index.html`，畫法在 `v2.js`）＝v2：**從 app 原版出發，只修轉接的顯示**。頁面並排「原版（現在的 app）」和「v2」。

- 原版膠囊左右的盾牌，意思是「左車道（南下／東向）能轉、右車道（北上／西向）能轉」。這和實際車道位置一致（北上車道在東側、南下在西側），而且最近的回饋問的都是「哪個方向的車道能做什麼」，依車道放剛好直接回答，所以版面、色條、膠囊都照原版。
- v2 只改三件事：只顯示真的能轉的方向、依「路線＋方向」去重、盾牌旁寫目標方向（「北上」「東向」）。
- 為什麼不用 v1：v1 的左右是「另一條路在地圖的哪一側」，回答不了「哪個車道能轉」（原開發者就讀錯過），只好再加方向方塊；遇到只能下／只能上、間接相連會越來越複雜，還要用座標算左右（27 筆平行判不出來）。
- v1（連續路面＋出口編號牌）的最後版本在 git tag `v1-final`，要參考時 `git checkout v1-final`。v1 學到的原則（幾 K 要醒目、字不要太多太粗、終點一律叫「{方向}終點」）之後可以拿來用。

## v2 待修（依優先）

### 畫面還沒做

1. **終點**：路走到底要標出來（台64 西向到八里二、台61 北上到淡水端、國3 北上到基金）。膠囊上寫「{方向}終點」，能轉的路牌照舊放在那個車道那一側。
2. **只能上來的入口**：台61 西濱（90K，接國3）只有南下能下去（出口）、只有北上能上來（入口）。現在只畫出口，入口要一種不同的記號（例如箭頭朝內）。資料要先確認（見「資料」）。
3. **轉進去馬上到終點的出口**：國3 木柵的「國3甲東向」只剩 0.6 km 就到深坑端，現在畫成「[3甲] 東向」；要改成「出口 往深坑」這類寫法。剩餘里程的算法在 `tools/link_geometry.py`（`remainKm`，≤2 km 算出口）。
4. **出口標誌寫了、但不是直接相連的道路**（國1 五股的 64、65：要先下一般道路再上，往 64 只能一個方向）。先定義「轉接」包不包含這種：
   - A. 只算系統交流道直接相連（現在的範圍）：五股不顯示，和出口標誌不一致。
   - B. 也算，但畫成「經一般道路」的另一種樣式，並標出能往的方向。
   - C. 不當轉接，另外列「出口接的道路」。
5. **主畫面、有事件時的小條**：還沒做。因為是依車道放，主畫面只顯示目前行駛方向那一側的轉接和終點；寫法和路況頁一樣（盾牌＋方向）。
6. **幾 K**：原版膠囊寫「2km」。使用者說大家看幾 K 判斷距離，要不要更醒目（例如「2K」、字大一點）再確認。

### 版面要找人看過確認

7. 兩邊都能轉同一條路時（國3 瑪東系統兩邊都是「62 東向」、台64 中和兩邊各兩塊國3），會不會又被讀成「左右都能走」？會的話，把記號貼近各自的色條，或加一句「左＝南下車道、右＝北上車道」。
8. 同一個車道能轉很多條時（國2 東向機場系統 4 條），膠囊會變很高，要用真的資料實測。

### 資料（要請後端確認或修正）

9. 台61 八里二：資料寫南下也能接 64 東向，實際只有北上能接。mockup 在 `shared.js` 用 `tr`（正確）＋`trRaw`（現有資料，給「原版」重現用）區分。
10. 出口和入口可能混在一起：台61 北上（博愛→西濱）和南下（龍鳳→西濱）都帶了「接國3 北上」；國3 南下（香山→西濱）帶了「接台61 北上」「接台61 南下」。要確認 `link2s` 的意思，補「這個方向可出／可入」。
11. 間接相連的候選：`tools/nearby_links.py` 找出「不同道路的交流道相距不到 1.5 km、資料沒有轉接」共 22 組（例如台65 五股端－國1 五股 0.38 km、台74 南屯二－國1 南屯、台61 竹南－國3 竹南、台62 暖暖－國1 基隆），要對照實際出口標誌。距離更遠的（國1 五股到台64 五股一／二）不在清單裡。
12. 出口接的一般道路：路網資料沒有（`links` 是偵測器編號），如果第 4 項選 C 要新建，最好分方向。
13. 路牌里程（`showKm`）和定位里程（`startKm`／`endKm`）有 22 處差超過 1 km：主畫面的「目前 xK」要換算成路牌里程，或請後端對齊。

### 寫進 app 時（程式，不是畫法）

14. `_buildSectionPairs` 依 index 配對兩個方向，台61 口湖會配錯；要依里程配對。
15. `_linksAtEndpoint` 用 `interchangeName` 或 `endName` 比對，可能把別段的轉接算進來；要依「抵達這個交流道的那一段」（南下 `…→i`、北上 `i+1→i`）判斷。
16. 去重改成「路線＋方向」（`_linksAtEndpoint`、主畫面的 `_uniqueRoadLinks`）；點路牌跳過去時只高亮那個方向（`connectedDirections` 只放 `link.dir`）。

### 文件

17. `spec.md`、`acceptance.md`、`app-integration.md` 是 v1（卡片）時期寫的，畫法不適用；要照 v2 重寫。資料欄位、剩餘里程演算法、app 相關程式的說明仍可參考。

## 怎麼接著做

- 看畫面：瀏覽器直接開 `index.html`。網址加 `?full` 展開整條列表、`#t64`／`#t61`／`#n3` 切情境。GitHub Pages：<https://jljimmyh.github.io/0924_road_veiw/>（有快取，更新後按 Ctrl+F5）。舊的 `v2.html` 會自動轉到首頁。
- 改畫法：`v2.js`（`olLiveScreen(sc, v2)`：`false`＝原版重現、`true`＝v2）、`shared.css`（`.ol-*`）。
- 情境資料：`shared.js` 的 `SCENARIOS`（節點、轉接 `tr`／`trRaw`、示意的出口道路 `exits`）、`REMAIN_KM`（出口用的剩餘里程）。`mainScreen`、`renderSmallBar`、`driveInfo` 是主畫面的外框與行車計算，做 v2 主畫面時可以用。
- 工具（都要讀解密後的路網 JSON，放在 repo 外，不要 commit）：`tools/link_geometry.py`（剩餘里程；左右是 v1 用的）、`tools/nearby_links.py`（找可能漏掉的轉接）。
- app 程式：`haodriveo_app` repo 的 `origin/jack` 分支，路況頁 `lib/pages/live/RoadLiveListModeWidfet.dart`、主畫面 `lib/pages/home/section/SectionWidget.dart`、資料 `lib/model/RoadSectionModel.dart`、`lib/provider/RoadDataProvider.dart`。
